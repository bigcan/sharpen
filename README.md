# FinRL-Pro_DS Scaffold

FinRL-Pro_DS extends the open-source FinRL Podracer project with institutional
workflow guardrails: reproducibility fingerprints, risk controls, structured
observability, and compliance-ready reporting. All new functionality lives
inside the `finrl_pro_ds/` namespace so upstream code remains untouched.

## Project Layout

- `finrl_pro_ds/` ??Python package containing training, evaluation, explainability,
  MLOps, and utility modules specific to FinRL Pro.
- `specs/` ??Source of truth for feature plans, task breakdowns, and API
  contracts generated by Spec-Kit.
- `docs/` ??Knowledge base for runbooks and extension workflows.
- `tests/` ??Pytest suite covering integration guards, reproducibility, risk,
  and reporting.
- `docker/` ??Container definitions for the FinRL Pro developer environment.
- `conf/` ??Environment overlays and `.env` samples for MLflow + DVC setup.

## Environment Setup

Requires Python 3.11. **CUDA-capable GPU is highly recommended for training.**

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .[dev]

# For GPU Acceleration (Required for large-scale training):
# Install PyTorch with CUDA support (adjust cu121 to your CUDA version)
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

# Optional formatters/linters if not installed globally
pip install ruff black mypy
```

Configure MLflow and DVC endpoints before running pipelines:

```bash
cp conf/finrl_pro_ds.env.example conf/finrl_pro_ds.env
dvc remote add -d finrlpro-s3 s3://finrl-pro-artifacts
dvc remote modify finrlpro-s3 endpointurl <S3_ENDPOINT>
# Bash/Zsh: export variables from .env safely
set -a; source conf/finrl_pro_ds.env; set +a
```

Windows PowerShell equivalent:

```powershell
Copy-Item conf/finrl_pro_ds.env.example conf/finrl_pro_ds.env
python -m venv .venv; .\.venv\Scripts\Activate.ps1; pip install -e .[dev]
# Load env vars from file (ignores comments and blanks)
Get-Content conf/finrl_pro_ds.env | ForEach-Object {
  if ($_ -and -not $_.StartsWith('#')) {
    $name,$value = $_ -split '=',2
    [System.Environment]::SetEnvironmentVariable($name,$value)
  }
}
```

## Core Workflows

- **Scaffold a module** inside the safe extension boundary:
  ```bash
  python -m finrl_pro_ds scaffold finrl_pro_ds.agents.new_agent \
    --doc "Custom FinRL Pro agent implementation"
  ```
- **Run a training job** that records reproducibility fingerprints:
  ```python
  from pathlib import Path
  from finrl_pro_ds.configs.fingerprint_store import FingerprintStore
  from finrl_pro_ds.training.trainer import Trainer

  store = FingerprintStore(manifest_path=Path("finrl_pro_ds/configs/fingerprints.yaml"))
  trainer = Trainer(fingerprint_store=store)
  trainer.run(
      config_path="finrl_pro_ds/configs/experiment_sp500.yaml",
      dataset_hash="dvc://datasets/sp500",

  evaluator = WalkForwardEvaluator(catalog=catalog)
  context = EvaluationContext(
      fingerprint_id="<fingerprint_id>",
      benchmark_id="sp500_rolling_1y",
      walk_forward_splits=3,
  )
  evaluation = evaluator.evaluate(context)

  pipeline = ReportPipeline()
  report = pipeline.generate(fingerprint_id=context.fingerprint_id, evaluation=evaluation)
  print(report.summary_location)
  ```

## Data Snapshots (DB-backed)

FinRL Pro is adding database-backed data snapshots to keep the database as the system of record and export files only when needed (see specs/001-db-snapshots/spec.md:1).

- Create a snapshot (stubbed CLI until DB plumbing lands):
  ```bash
  python -m finrl_pro_ds.data.snapshot --provider yahoo \
    --tickers SPY,AAPL --start 2020-01-01 --end 2024-01-01 --interval 1d
  ```

- Export a snapshot to a file (stubbed):
  ```bash
  python -m finrl_pro_ds.data.export_snapshot --id <snapshot_id> --out data/snapshots --format parquet
  ```

- Use a snapshot in experiments by setting:
  ```yaml
  dataset_hash: snapshot://<snapshot_id>
  ```
  For training, the Pro loader (`finrl_pro_ds/data/loader_pro.py`) queries the DB and assembles arrays for the env.

### Database Quick Start (Timescale/PostgreSQL)

- Run TimescaleDB locally via Docker:
  ```bash
  docker run --name finrl-timescale -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d timescale/timescaledb:latest-pg16
  # Create database (first time):
  docker exec -it finrl-timescale psql -U postgres -c 'CREATE DATABASE finrl_pro_ds;'
  ```
- Set DSN in your environment (or `conf/finrl_pro_ds.env`):
  ```bash
  export FINRL_PRO_DB_DSN=postgresql://postgres:postgres@localhost:5432/finrl_pro_ds
  ```
- Schema is initialized automatically by `DatabaseClient.init_schema()` the first time snapshot/export is invoked (will try `CREATE EXTENSION timescaledb` if available).

## Feature Engineering (Pro) and Dynamic Env

- Configure features per experiment in `finrl_pro_ds/configs/experiments/*.yaml`:
  ```yaml
  features:
    enable_custom: true
    use_turbulence: true
    families: { trend: true, momentum: true, vol: true, volume: false }
    advanced:
      fracdiff: { enable: true, cols: [close], d: 0.5, window: 256 }
      wavelet:  { enable: false, cols: [close], wavelet: db4, level: 3, window: 256 }
  ```
- Assemble arrays from a snapshot and create a dynamic env (arbitrary `tech_dim`):
  ```python
  from finrl_pro_ds.data.loader_pro import ProFeatureAssembler
  from finrl_pro_ds.envs.factory import make_pro_env

  asm = ProFeatureAssembler(dsn=os.getenv("FINRL_PRO_DB_DSN")).assemble_from_snapshot(
      snapshot_id="<uuid>", features_cfg=YOUR_FEATURES_CFG)
  env = make_pro_env(asm)
  ```
- Reuses features via the DB feature store keyed by `features.cache_key`.

## Risk & Observability Guardrails

- Define capital exposure thresholds in `finrl_pro_ds/configs/risk_profiles.yaml`
  and load them with the helper in `finrl_pro_ds.mlops.risk_profiles` before training.

  Example:

  ```python
  from pathlib import Path
  from finrl_pro_ds.mlops.risk_profiles import load_risk_profile, RiskControlPolicy

  profile = load_risk_profile(Path("finrl_pro_ds/configs/risk_profiles.yaml"), "default")
  policy = RiskControlPolicy(profile)
  ```
- `RiskControlPolicy` enforces drawdown/capital/leverage plus the optional
  turnover (`max_avg_turnover`) and transaction-cost (`max_transaction_costs_bps`)
  budgets so PSR gains cannot come from unchecked churn.
- Structured logs flow through `finrl_pro_ds.mlops.logger.MLOpsLogger`, emitting
  JSON payloads suitable for centralized observability tooling.
- Risk alerts are routed by `finrl_pro_ds.mlops.alerting.RiskAlertDispatcher` and
  raised automatically when drawdown, leverage, or sandbox policies are
  violated.

## DeepScalper Replication

Work-in-progress replication of the DeepScalper architecture (Sun et al., 2022) for minimal latency intraday trading on Bitcoin Futures.

- **Agent**: `finrl_pro_ds.agents.deepscalper` (Synapse Ensemble: DQN, PPO, A2C)
- **Environment**: `finrl_pro_ds.envs.deep_scalper_env.DeepScalperEnv` (LOB-aware, T+1 latency)
- **Data**: TimescaleDB storage for high-frequency LOB snapshots (`finrl_pro_ds.data.db.LOBSnapshot`)

Run DeepScalper tests:
```bash
pytest tests/deepscalper
```
