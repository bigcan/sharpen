## Executive Summary

The pipeline is, once again, **strong below the waterline and hollow at the decision layer**. The low-level correctness machinery is genuinely excellent and adversarially proven: the X2 coarse-bar map is fixed and tripwired in both handlers, LEAK-1 per-split isolation holds under perturbation, the DSR formula is mutation-tested to a hand-computed golden, the SimFillEngine reproduces the env cost model line-for-line (parity 0.0 on real ETF data), the forward-path independent-recompute escape hatch is adversarially tested for both sleeves, and the PSR/MinTRL backstop is wired with the correct per-period (`periods_per_year=1`) calibration and a mutation tripwire. None of that is the problem.

**The single dominant cross-cutting fault — DECLARED-BUT-NOT-WIRED gates.** The same pattern recurs at *every* stage of the lifecycle: a safety gate is documented in `protocol_v2.md` / a `gates.yaml`, the *detector* is even built and unit-tested, but **no consumer on the active workstream's path actually reads its verdict**, so a FAIL-earning condition still drives the deploy-gating decision. It appears as: the data-manifest stale/freshness `status` is earned but never read (P1-01/P1-02/P1-03); the rates-carry sleeve bypasses DATA-CLEAN entirely (P1-04/P1-05); the training-health kill gates and the manifest `training_health` block have zero readers (P5-01/P5-06); the training-budget multiplicity and the 22-month calendar minimum silently skip every session-bound and full-train-WF path (P5-02/P5-11/P6-06); the live-bound allocator runs **no Stage-2 multiseed and is unseeded** (P6-04); its declared L1 gate keys have no consumer and the pipeline never calls `validate_config` (P6-05); §4.5 retrain triggers are SAC-hardcoded and unreachable for the linear core (P10-01); the north-star cross-sleeve diversification gate is `DEFERRED`/unwired while its only wired proxy (corr-to-SPY 252d = 0.53) already FAILs (P10-05); and the DATA-CLEAN stale-print gate is not fail-closed (P10-03).

**Top S1 theme — the live-bound strategy's deploy evidence does not exist yet.** The one S1 (P6-04) is that the strategy actually heading to capital (the cross-asset momentum allocator) has **no l1-multiseed stage at all and passes no `seed=` to SAC** — every HPO trial and every per-window full-train is a single non-deterministic run, so the deploy-gating WF verdict rests on one un-seeded run per window, in direct violation of Protocol v2 Principle 6 ("multi-seed median, not max"). Capital promotion is *currently* blocked pending an operator Tier-2 audit + rung-2, which is the only reason this is gated rather than already-deployed.

**Top S2 themes:**
1. **Multiple-testing / selection-bias is uncontrolled on the deployable book.** The momentum+rates-carry 0.601 headline is a multiple-comparison winner (~18-20 momentum books graded × a 3-class carry test whose pooled verdict was NO_GO, with rates the lone selected survivor) and nothing deflates for it — no Deflated-Sharpe, no PBO/CSCV. PSR is wired but at `benchmark=0`, which is *not* a multiplicity control; the project's own honest re-eval already shows the +0.21 carry uplift **reverses OOS** (P11-01/P11-02/P11-03/P9-04). The DSR primitive already exists in the options-VRP sleeve — this is a port, not a build (P11-09).
2. **Causality tripwires have a current-bar blind spot, and the keystone parity check doesn't recompute the signal.** `assert_causal` only perturbs *strictly-future* bars, so a current-bar (`skip=0`) leak passes silently — the exact X2 lesson (a green tripwire that doesn't cover the line where the bug would live), confirmed live (P2-01). Worse, the step-4 pre-capital weight-drift keystone re-derives conviction from the *already-computed* `conviction_ary`, not from `cas.compute` on raw prices, so a leak inside the signal compute would be baked identically into oracle and "independent" recompute → drift 0 (P2-02).
3. **Calibrations are stale relative to the object they now govern.** The always-on DD/daily-loss kills (50% / 12%) are calibrated to the *retired single-sleeve* daily-rescale render (42.8% / -9.77%), but the executor now runs the *two-sleeve* fund-of-funds (~20% DD / -5% worst day), so a genuine break passes silently (P8-07). The cost-basis of the GO headline (flat 2bps, SR 0.60) differs from the env participation-cost render the paper soak validates (~0.441), and the live config's risk gates do not blanket-skip — but they no longer fit (P10-06).
4. **Stress / OOS gates measure the wrong or a censored signal.** The fixed-lot stress faithfulness guard watches `prop_firm_termination`, which the bare env never emits — so a DD-wall-truncated path is certified "exact" and the true worst DD is censored at the 30% wall (P7-01/P7-08); G2/G3/G4/G5 then aggregate over non-comparable censored windows (P7-02/P7-09); and the active allocator has **no held-out Stage-4 OOS** — its "validation" runs on the full 2006→2026 window the GO was derived on, with `ParityHarness` parity being a tautology by its own docstring (P8-06). Two legacy gmgp1-btc OOS artifacts still read PASS at +5,438% / PF 2.149 with no `superseded_by` pointer (P8-01/P8-02), albeit on a shelved, non-capital-wired strategy.

**Credit where due (S4 positives, ~30):** the X2 coarse→base causal map + non-vacuous tripwires in both handlers (P2-05); LEAK-1 isolation under adversarial perturbation (P2-06); the shipped NOW-priority LEAK-2 truncation/escape tests (P2-07/P10-10); correct decide-t/earn-t→t+1 step ordering with a *real-env* golden trajectory test (P3-01/P3-02); SHORT-ACCT debt-free across the active path (P3-03); non-zero slippage in the active cost model (P3-04); the DSR mutation tripwire and cost-effectiveness-despite-scale-invariance (P4-01/P4-04); cost-aware HPO PF objective + deploy allowlist (P4-08/P5-09); correct LEAK-1 norm-cutoff on the HPO eval path (P5-10); the val-correct `collect_reconcile_x1` template (P6-11); the velotrade ensemble engine's chosen_rule/graded_rule + X3 stress override (P9-08); strict gates-from-YAML sourcing in the ensemble engine (P9-09); net-of-cost L1 eval + LEAK-1 (P6-10); WF non-overlapping folds + BUG-03 zeroing + conservative stress semantics (P7-05/P7-06/P7-07); line-for-line sim↔live cost/accounting parity (P10-09); and the mathematically-correct, mutation-verified PSR/MinTRL backstop (P10-11/P11-08), with the deflated-Sharpe primitive already in-repo (P11-09).

**Verdict:** The machinery will protect capital from a coding-leak blow-up, but it will **not yet certify a robust, consistent, uncorrelated sleeve** because (a) the live-bound strategy has no seeded multiseed and no held-out OOS, (b) the deployable edge is unprotected against the very multiple-testing that produced it, and (c) a dozen safety gates are detectors with no consumer. Capital remains correctly BLOCKED. The fixes are about making the *next* promotion's evidence real — most are NOW-bucket wiring/config/test work that needs no retrain.
